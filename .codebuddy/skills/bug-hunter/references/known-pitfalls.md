# C++ JSON 序列化/反序列化库常见易错点

## 1. 字符串处理

### 1.1 JSON 转义不完整

JSON 规范要求以下字符必须转义：

| 字符 | 转义形式 | 常见遗漏 |
|------|---------|---------|
| `"` | `\"` | 少见遗漏 |
| `\` | `\\` | 少见遗漏 |
| `\n` | `\\n` | 偶尔遗漏 |
| `\r` | `\\r` | 经常遗漏 |
| `\t` | `\\t` | 偶尔遗漏 |
| `\b` | `\\b` | 经常遗漏 |
| `\f` | `\\f` | 经常遗漏 |
| `\0`-`\x1F` | `\\u00XX` | **最常遗漏** |

**TinyReflection 已知问题**：`char` 类型的序列化可能未做转义处理。

### 1.2 Map Key 转义

`map<string, T>` 的 key 在序列化为 JSON 时也需要转义，但很多库只转义 value 中的字符串，忘记转义 key。

**TinyReflection 已知问题**：`to_json_key` 函数可能未做转义。

### 1.3 含 Null 字节的字符串

`std::string` 可以包含 `\0` 字节，但 JSON 字符串不能。序列化时需要转义为 `\u0000`，反序列化时需要正确还原。

### 1.4 Unicode 处理

- UTF-8 多字节序列的正确传递
- 代理对（surrogate pairs）的处理
- BOM（Byte Order Mark）的处理

## 2. 数值处理

### 2.1 浮点特殊值

JSON 规范**不支持** `Infinity`、`-Infinity`、`NaN`。常见处理方式：

- 序列化时输出 `null`
- 序列化时报错
- 序列化时输出字符串 `"Infinity"`

**TinyReflection 已知问题**：`inf`/`nan` 可能被直接输出为字面量，产生非法 JSON。

### 2.2 整数精度

- JSON 数字理论上无限精度，但 JavaScript 的 `Number` 只有 53 位有效位
- `int64_t` 超过 `2^53` 的值在与 JavaScript 交互时可能丢失精度
- 库自身的 roundtrip 应不受影响，但需确认解析器使用 `int64_t` 而非 `double`

### 2.3 数值溢出

反序列化时，JSON 中的大数可能溢出目标类型：

- `int` 字段接收 `int64_t` 范围的值
- `float` 字段接收 `double` 范围的值
- 负数赋给无符号类型

### 2.4 -0.0

`-0.0` 在 IEEE 754 中是合法值，序列化时可能输出 `-0` 或 `0`，roundtrip 后可能变为 `0.0`。

## 3. 结构体/对象映射

### 3.1 字段顺序

- 序列化时字段顺序是否与结构体声明顺序一致
- 反序列化时 JSON key 的顺序是否影响结果（不应影响）

### 3.2 缺失字段处理

当 JSON 中缺少结构体某个字段时：

- 保持默认值（最常见）
- 报错（更严格）
- 未初始化（bug）

**关键测试**：反序列化 `{}` 到有多个字段的结构体，检查各字段是否为默认值。

### 3.3 多余字段处理

当 JSON 中有结构体没有的字段时：

- 忽略（最常见）
- 报错（更严格）
- 导致解析器状态错误（bug）

**关键测试**：反序列化含多余字段的 JSON，检查已知字段是否正确填充。

### 3.4 嵌套结构体

- 内层对象为 `null` 时如何处理
- 内层对象为空 `{}` 时如何处理
- 内层对象字段不完整时如何处理

## 4. 容器处理

### 4.1 空容器

- `vector<T>{}` 序列化为 `[]`
- `map<K,V>{}` 序列化为 `{}`
- `[]` 反序列化为空 vector
- `{}` 反序列化为空 map

### 4.2 unordered_map 顺序

`unordered_map` 的迭代顺序不确定，序列化结果的 key 顺序可能每次不同。Roundtrip 测试时不应直接比较 JSON 字符串，而应逐字段比较对象。

### 4.3 嵌套容器

- `vector<vector<int>>` — 二维数组
- `map<string, vector<int>>` — 对象内含数组
- `vector<map<string, int>>` — 数组内含对象

### 4.4 容器元素为自定义类型

`vector<CustomStruct>` 要求对 `CustomStruct` 的序列化/反序列化也正确，错误可能在嵌套时才暴露。

## 5. 类型系统

### 5.1 类型特征误判

- `const char*` 是否被正确识别为字符串类型
- `char` 是否被当作整数还是字符处理
- `unsigned int` / `size_t` / `short` 等非标准宽度整数的处理
- `enum` / `enum class` 的处理

### 5.2 `ignore<T>` 标记

- 序列化时确实跳过
- 反序列化时不期望 JSON 中有对应字段
- `ignore<T>` 的默认值是否正确初始化

### 5.3 智能指针

- `shared_ptr<T>` / `unique_ptr<T>` 通常被标记为跳过
- 如果支持，需要处理 null 指针的情况

## 6. SAX 解析器状态管理

### 6.1 Handler 栈

基于 SAX 的反序列化器通常使用 handler 栈管理嵌套：

- 进入对象时 push handler
- 离开对象时 pop handler
- 栈不匹配会导致字段赋值到错误的对象

**关键测试**：多层嵌套结构体的反序列化后，检查每一层的字段值。

### 6.2 数组元素类型切换

解析 `vector<CustomStruct>` 时，每个数组元素都需要 push 新的 handler：

- 第一个元素正确但第二个元素错误 → handler 未正确重置
- 空数组后接非空数组 → 状态未清理

### 6.3 错误恢复

解析中途遇到错误时，handler 栈是否正确清理，后续调用是否安全。

## 7. 内存安全

### 7.1 `const char*` 悬空指针

反序列化时，`const char*` 字段通常指向临时分配的内存，函数返回后可能失效。

### 7.2 字符串引用

如果库内部使用 `string_view` 引用 JSON 输入缓冲区，在输入被释放后引用失效。

### 7.3 大输入

- 超深嵌套 JSON（栈溢出风险）
- 超长字符串（内存分配失败风险）
- 超大数组（内存分配失败风险）
